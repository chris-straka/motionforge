# Code review, 2026-11-13

An earlier audit listed ten findings. Each was checked against the code
at `2a0b566` (the line numbers it gave were from an older tree; current
ones are below). Verdicts: **bug** (wrong output, fixed in this round),
**limit** (works as designed, but the design falls short; on the plan),
**stale** (no longer true), **not confirmed**.

| # | finding | verdict | where now | what was done |
|---|---|---|---|---|
| 1 | stylizer, physics fix, limits and AutoPose live on the clip-JSON path, not in `animate` | **limit**, partly stale | `cli/src/glb_cmds.rs:181` (`cmd_animate`), `core/src/stylize_body.rs:438` (`stylize_glb`) | The stylizer runs on GLBs since `c599ace` (`motionforge stylize --input x.glb`), but `animate` cannot call it; physics, limits and AutoPose read clip JSON only. Wiring the GLB stylizer and a clean-up pass into `animate` is this round's main work (`docs/log.md`). |
| 2 | stylizer keys each bone on its own clock, never re-plants feet, can't run on GLBs, exaggerates from rest | **stale** for GLBs, true for clip JSON | per-bone: `core/src/stylize.rs:197-212`; body mode: `stylize_body.rs:299-380` | Body mode (default on GLBs) has shared keys, one clock, exaggeration about the clip's mean pose (`stylize_body.rs:353`) and re-planted feet (`stylize_body.rs:712`). The Blender operator still sends clip JSON, so it still gets the per-bone mode. |
| 3 | retarget has no hand targets or joint limits | **limit** | `core/src/animate.rs:224-277` (`Transfer::frame`) | True: rotations are copied, then only feet (pinning) and arms-out-of-body (contact pass) are corrected. A hand on a hilt or a hip drifts when arm lengths differ. Joint limits: the new `motion check` limits score (below) measures it; nothing clamps yet. |
| 4 | foot pinning is sideways-only | **limit** (real) | `core/src/footpin.rs:46,153` | `flat()` drops height: a plant keeps its place on the floor but not its height, so a target whose shin/thigh ratio differs from the source's floats or sinks while planted. Height pinning is on the list (`docs/log.md`). |
| 5 | physics momentum fix is a blur | **limit** (real) | `core/src/physics.rs:532-575` | It Gaussian-smooths the root's horizontal path around flagged frames. Because only the root moves, a planted foot slides by the same amount. Clip-JSON path only; the game's clips never go through it. Not fixed this round. |
| 6 | `standardize` uses one inverse bind matrix per joint for every skin | **bug, fixed** | `core/src/standardize.rs:296-318`, `skin_ibm` at `:457` | Every skin got the first skin's matrices. A second mesh bound in another space moved by that offset (test: 0.3/-0.2/0.5 m exactly). Each skin now keeps its own table (identical tables shared, so one-skin files are unchanged); a joint a skin never had gets that skin's bind carried over. Test `standardize_keeps_each_skins_own_bind` fails on the old code. |
| 7 | `compact` can leave stale accessors | **bug, fixed** (malformed input only) | `core/src/glb.rs:129` | On a buffer view running past the BIN chunk it gave up halfway: the meshes' accessor indices were already renumbered, the accessor list was not, so every reference pointed at the wrong data. It now checks every view first and leaves the file untouched. Tests `compact_drops_dead_accessors_and_keeps_references_right`, `compact_leaves_a_malformed_file_whole`. |
| 8 | tests at `glb.rs:762,795` can't fail | **not confirmed** | `glb.rs:752-797` (old tree) | Those are the container round trip and the affine inverse/decompose tests; both assert concrete values (the accessor rows read back, `inverse(apply(p)) = p`, the decomposed translation, rotation and scale), so a broken reader or decompose fails them. |
| 9 | `tools/tripo_rig.py` ignores a failed `animate` | **bug, fixed** | `tools/tripo_rig.py:104` (`apply_step_failures`), `:283` | A human whose clips failed to retarget was judged on the bare rig and could be reported as passing. A failed `animate` now fails the try with the reason first in its list. |
| 10 | `tripo_rig.py` accepts a stale fixed file | **bug, fixed** | `tools/tripo_rig.py:253,272` (`fresh`) | When `weights fix` failed, a `try_s<seed>.glb` left by an earlier run was taken as its output (the exit code was not read). The old file is removed first and a non-zero exit is a failure; same for the clip retarget's output. Tests in `tools/tests/test_tripo_rig.py`. |

## Found on the way

- **The game's `sf_*` clips stand in the floor to the waist** (all seven,
  86-93 cm): in those clips the hips' local height is about -1.0 under a
  root at +1.0; in every other clip it is about 0. HLH's provenance says
  the Kimodo takes were copied onto the rig with "hips centred", which
  matches. That is in HLH's file, not this repo; a ground step for
  the game's own clips is next (`docs/log.md`).
- **The enemy, Quirin and enemy-death takes float 7-41 cm on every
  frame.** Same kind of offset in the clips.
- `motion check`'s jerk ranks fast moves as rough (it was the earlier
  session's own caveat); a roughness measure that a fast clean arc does
  not trip is next (`docs/motion-check.md`).
